# Research: a Windows installer for PlayMap with no paid services

*Scope: how PlayMap (a .NET 10 desk + engine, with a LocalSystem supervisor service) is installed per machine on Windows 11
(Home included), unsigned for now, built on GitHub Actions `windows-latest`, without any paid WiX service. Facts are as of
October 2026, from the sources listed at the end. Each claim carries a confidence mark: **[H]** high (primary source read),
**[M]** medium (secondary source or inference), **[L]** low (unverified).*

---

## 0. Bottom line

**Recommendation: keep the plan's WiX v7 MSI, but build the WiX toolset from its MS-RL source at a pinned release tag in CI and
never consume WiX's official binaries (GitHub releases, NuGet packages, the `wix` .NET tool, the extensions).** Inno Setup 7 is the
named fallback if a time-boxed spike cannot build WiX on the runner.

Why, in five lines:

1. The OSMF EULA binds only WiX's *Binary Release*; it says in terms that a user "may independently compile binaries from the
   Software's source code without this Agreement" **[H]**. The OSMF FAQ says the same: "Do not download releases. Do not reference
   packages via a package manager" if you do not pay **[H]**. Velopack ships its MSIs from its own WiX v7 build on exactly this
   reading **[H]**. No fee, no EULA gesture, at any revenue level.
2. It keeps `design/installer.md` intact: a per-machine MSI, `ServiceInstall`/`ServiceControl` with failure actions,
   `MajorUpgrade` and its refusal words, a launch condition, an immediate custom action (the armed check) before `InstallValidate`,
   a deferred one (the privilege grant), the firewall extension, transactional rollback, `msiexec /qn` for IT.
3. WiX v7 is the security-supported line; v5 (the last fee-free *binary*) has had no community security fixes since February 2026
   **[H]**.
4. The `windows-latest` image already carries what WiX's own build asks for: Visual Studio 2026 (18.10), .NET SDK 10.0.401,
   NuGet 7.9 **[H]**; whether every C++ component (ATL, ARM64/Spectre libraries) is present is the spike's first question **[M]**.
5. Every alternative that is free either is not an MSI (Inno Setup, NSIS), cannot do the machine-level actions the node needs
   (MSIX, ClickOnce, Velopack), or still depends on WiX binaries (WixSharp) or on Visual Studio's IDE build (Installer Projects).

**Confidence in the recommendation: medium-high.** High on the licensing reading (not legal advice); medium on the engineering cost
of building WiX on the runner until the spike has run.

## 1. What the installer has to do (from the round-3 design)

From `docs/round3/design/installer.md` and `PLAN.md` D6, §3.5:

- one per-machine install to `%ProgramFiles%\PlayMap\` (self-contained, ReadyToRun publish; FFmpeg's LGPL libraries as replaceable
  files; the Agility SDK; the supervisor);
- `PlayMapSupervisor`: LocalSystem, automatic, recovery actions (5 s, 30 s, then none, reset after a day, non-crash failures too);
- firewall rules for `PlayMap.exe` (TCP 9940/9941, UDP 9928/9942/9943/6454/5568/5353), WER LocalDumps keys, an event source, two
  privileges for the show account through the supervisor's `grant`/`revoke` as a deferred action;
- an armed check before anything is replaced (fail closed, with the node's words);
- `MajorUpgrade` with no same-version upgrade and a downgrade refused with words; `ProductVersion` MAJOR.MINOR.BUILD;
- a Windows build launch condition (26100+); x64 only;
- unsigned builds named `-unsigned` until the signing decision is made (owner: "Leave unsigned for now").

The engine itself never runs as a service: services live in session 0 and "cannot directly interact with a user as of Windows
Vista" **[H]**; the documented way for a LocalSystem service to start a process in the console session is
`WTSQueryUserToken(WTSGetActiveConsoleSessionId())` + `CreateProcessAsUser` **[H]** — which is what the plan's supervisor does (M9).

## 2. WiX Toolset licensing, precisely

### 2.1 The source licence (MS-RL)

- WiX's source is under the Microsoft Reciprocal License (MS-RL) **[H]**. MS-RL is file-level reciprocal: a distributed file that
  contains WiX code must come with its source and the licence; your own files may carry any terms **[H]**.
- The .NET Foundation (and Outercurve before it) states that "the installer packages generated by WiX will normally fall outside the
  scope of the MS-RL" and that your components inside them "can be governed by other licensing terms" **[H]**.
- What an MSI *does* carry from WiX: the custom-action DLLs of any extension used (Util for `ServiceConfig`/failure actions and
  quiet exec, Firewall for the rules). Those DLLs stay MS-RL files: name them in `THIRD-PARTY-NOTICES.md` with the licence text and
  a link to the exact source tag (one published example: Setliner's notice for WiX's Util CA DLL) **[H]**. If PlayMap ever patches
  WiX files, those patched files are published under MS-RL.

### 2.2 The Open Source Maintenance Fee (OSMF)

| WiX line | Binary releases under | Fee for a revenue-generating user | EULA gesture | Community security fixes |
|---|---|---|---|---|
| v3, v4 | MS-RL only | none | none | ended Feb 2025 **[H]** |
| v5 (5.0.2, Oct 2024) | MS-RL only | none ("WiX v5 is out of service and will not have the fee applied") **[H]** | none | ended 5–6 Feb 2026 **[H]** |
| v6 (6.0.0 Apr 2025 – 6.0.2 Aug 2025) | OSMF EULA **v1.0** | yes, **no revenue threshold** **[H]** | none (EULA ID "N/A") **[H]** | until 5 Feb 2027 **[H]** |
| v7 (7.0.0, 6 Apr 2026) | OSMF EULA **v1.1** | yes once the user's annual gross revenue is **≥ US$10 000** **[H]** | required: `-acceptEula wix7`, `<AcceptEula>wix7</AcceptEula>`, or `wix eula accept wix7`; without it the build fails with WIX7015 **[H]** | current line (security fixes for current + previous major, 10 months after the next release) **[H]** |
| any version, **compiled from source** | MS-RL only | **none** — outside the agreement (EULA §4) **[H]** | none (the agreement does not apply; whether the self-built tool still runs the check is unverified **[L]**) | you rebuild from the upstream tag |

What the fee covers and who pays:

- **Binaries, not source.** "Binary Release" means "pre-compiled executable versions of the Software provided by Project"; the fee
  "is not a license fee"; the source "remains freely distributable under the terms of the OSI License" **[H]**.
- **Related services too.** The WiX README: "all other aspects of the project—including opening or commenting on issues,
  participating in discussions and downloading releases—require adherence to the Maintenance Fee" **[H]**. A fee-free user reads the
  code and the docs, and does not file issues.
- **Threshold wording.** The v1.1 EULA and the OSMF FAQ tie the threshold to the *user's* (organisation's or individual's) annual
  gross revenue **[H]**; the WiX v7 blog phrases it as revenue "from your projects that use WiX" **[H]**. Read the stricter text: an
  organisation over $10 000 a year owes it even if PlayMap itself is free — the OSMF FAQ says so explicitly ("Yes … based on whether
  the software is used as part of revenue generating activities and whether the organization meets the minimum revenue threshold,
  not on whether the product itself is sold") **[H]**.
- **Amount.** The OSMF norm is "$10 per month per project", paid through GitHub Sponsors; WiX's 2025 proposal listed $10 / $40 / $60
  a month by organisation size (<20, 20–100, >100 people) **[H for the proposal; current tiers on the sponsor page not re-read, M]**.
  One payment covers every product of the organisation **[H]**.
- **Transitive use.** You pay only projects you depend on directly; a build tool you adopt for CI counts as direct **[H]**. So WiX
  consumed inside another tool's own self-built fork (Velopack's) is not a fee for PlayMap; WiX's official NuGet packages referenced
  by PlayMap's `.wixproj` are.

### 2.3 Under vs over $10 000

| Route | Organisation under $10 000/yr | Organisation at or over $10 000/yr |
|---|---|---|
| Official v7 binaries | free; must accept the EULA in CI (`AcceptEula`) | fee due (a paid WiX service — excluded by the owner) |
| Official v6 binaries | fee due if revenue-generating at all | fee due |
| Official v5 binaries | free, no gesture; no security fixes since Feb 2026 | same |
| **v7 compiled from the tagged source** | **free, no gesture, no EULA** | **free, no gesture, no EULA** |

Building from source is the only route that is free regardless of the owner's revenue now or later, and that needs no attestation
in CI that could become false when revenue crosses the line.

### 2.4 What building WiX from source takes

- The WiX README: Visual Studio 2026 (18.6 or higher) with ASP.NET, .NET desktop and C++ desktop workloads; .NET 10 runtime; .NET
  Framework 4.8 SDK and the 4.7.2 / 4.6.2 targeting packs; MSVC ARM64/ARM64EC build tools and Spectre libraries; ATL for
  x64/x86/ARM64; Git; `nuget.exe` on the path; then `devbuild release` from a VS 2026 developer prompt **[H]**. WiX moved its own
  build to the .NET 10 SDK and VS 2026 in Dec 2025 (needs NuGet 7) **[H]**.
- `windows-latest` is Windows Server 2025 with Visual Studio 2026 Enterprise 18.10, .NET SDK 10.0.401, NuGet 7.9, Windows SDK
  10.1.26100 **[H]**. The ATL/ARM64/Spectre components are not individually confirmed on the image **[M]**.
- A known upstream issue: WiX 7.0.2's `devbuild` tests fail to find MSBuild when only VS 2026 is installed (issue 9261, open in
  March 2026) **[H]**. The spike may need to build the packages without that test leg, or patch the version range the issue names.
  (PlayMap's own tests are never skipped; this is a third-party tool's internal suite, and the spike records what it ran.)
- Burn (bundles) is not needed: PlayMap ships one MSI, so only the core toolset, the SDK and the Util and Firewall extensions are
  consumed.
- The output is a set of `.nupkg` files (`WixToolset.Sdk`, `WixToolset.Util.wixext`, `WixToolset.Firewall.wixext`, …) **[M]**.

**How PlayMap would consume it** (proposal):

1. A `wix-toolset` CI job checks out `wixtoolset/wix` at a pinned tag (e.g. `v7.0.x`), builds release packages, and caches them
   keyed by the tag's commit; the packages carry a version suffix of PlayMap's own so they can never be confused with nuget.org's.
2. `nuget.config` maps `WixToolset.*` to that local folder only (NuGet package source mapping), so a restore can never fetch an
   official WiX package — fail closed.
3. An `InstallerTests` assertion: the restored `WixToolset.Sdk` comes from the local feed and its hash matches the cached build.
4. `THIRD-PARTY-NOTICES.md`: "WiX Toolset, built from source at tag …, as a build tool; its Util and Firewall custom-action DLLs
   inside the MSI, MS-RL, source at …".
5. Upstream security releases are watched (tags and the FireGiant release notes), rebuilt and re-pinned; no issues are filed.

### 3.2 Notes per tool

**MSIX.** Sideloading is on by default on Windows 11 **[H]**. Services are supported from Windows 10 2004 with the restricted
capabilities above and admin elevation **[H]**; kernel drivers and services depending on services outside the package are not
**[H]**. Unsigned MSIX exists only as a developer convenience: the manifest's publisher must carry the special OID
`2.25.311729368913984317654407730594956997722`, it installs only with `Add-AppxPackage -AllowUnsigned` from (usually elevated)
PowerShell, and Microsoft says "Don't use this feature to distribute your app widely" **[H]**. Otherwise the signing certificate must
be trusted on the machine. MSIX also runs SmartScreen reputation checks (`ERROR_PACKAGES_REPUTATION_CHECK_FAILED`) **[H]**. The
plan's machine-level writes (HKLM keys, WER LocalDumps, LSA rights for a named account) do not fit a package model built to keep
writes contained; `PLAN.md` D6 already rejects it.

**Inno Setup.** Inno Setup 7 (May–Aug 2026) adds a 64-bit compiler and 64-bit installers (`SetupArchitecture=x64`,
high-entropy ASLR), extended-length paths, `--messages-jsonl` for CI, and keeps backward compatibility with 6.x **[H]**. It has no
services section; the standard patterns are `sc.exe create/failure/delete` in `[Run]`/`[UninstallRun]` (with `RunOnceId`) or a
Pascal wrapper over the SCM API for error handling **[H]**. For PlayMap the cleaner pattern is the supervisor's own C# verbs
(`install`, `uninstall`, `grant`, `revoke`, `preinstall-check`) — unit-testable in .NET and identical under any packager. A
downgrade refusal and the armed check go in `InitializeSetup`. The commercial-licence request (perpetual, two years of updates) is a
request, not a condition; the owner decides whether to honour it **[H]**.

**NSIS.** Free with no request; latest 3.13 (27 Sep 2026), with privilege-escalation fixes in 3.11 and 3.12 for installers run as
SYSTEM **[H]**. Everything (upgrade detection, downgrade refusal, service, firewall) is script; there is no rollback engine
**[M]**.

**WixSharp.** MIT; it does not ship WiX ("WixSharp does not distribute WiX Toolset") and runs whichever `wix` is installed, so it
works with a self-built WiX as well **[H]**. It replaces `.wxs` with C#; PlayMap's design already writes `.wxs`, so it adds a layer
without removing the licensing question.

**Windows Installer API directly.** All free and native: `MsiOpenDatabase`, `MsiDatabaseImport`/views to write tables,
`MsiGetFileHash`, summary information, cabinets through `cabinet.dll`'s FCI, ICE validation with the Windows SDK's tools. WiX's
DTF wrapper is itself a WiX binary (OSMF if official). The cost is authoring and validating some 40 tables, sequences and dialogs:
weeks, and a generator PlayMap would own forever. `msitools`' `wixl` (LGPL; runs on Linux, not on Windows) builds a subset of WiX
syntax including services but "lacks many features compared to WiX" **[H]**; it would be run as a tool, never copied.

**dotnet tooling.** The .NET SDK has no installer: `dotnet publish -r win-x64 --self-contained -p:PublishReadyToRun=true` feeds any
packager. ClickOnce is per-user and writes nothing to Program Files or the registry **[H]**: no supervisor service. Microsoft's
winapp CLI (public preview, v0.3 in April 2026) packages any framework — Avalonia included — as MSIX **[H]**, so it inherits MSIX's
limits.

**Velopack.** Its MSI now installs per machine and supports GPO/SCCM, but it adds no services, offers no custom tables, and its
model is a self-updating app — the opposite of "show machines never auto-update" (`docs/COMPETITIVE.md`). It is, however, public
evidence that a product can ship MSIs from a self-built WiX v7 without the fee **[H]**.

## 4. Unsigned behaviour (the owner: "Leave unsigned for now")

Applies equally to MSI, Inno and NSIS EXEs:

- **SmartScreen (Mark-of-the-Web).** Browsers and mail clients tag downloads with a `Zone.Identifier` stream; Explorer and many
  archivers propagate it to extracted files **[H]**. SmartScreen then shows "Windows protected your PC … Unknown publisher"; the user
  must press **More info → Run anyway**; enterprise policy can remove that choice **[H]**. Unsigned files "must build reputation
  anew with every update" — reputation never carries from one unsigned build to the next **[H]**. EV certificates no longer bypass
  SmartScreen **[H]**. Files copied from a LAN share or USB stick, or fetched with `curl`/PowerShell, usually carry no MotW and are not
  checked **[M]**.
- **UAC.** The elevation prompt for an unsigned MSI/EXE names "Unknown publisher" **[M]**.
- **Smart App Control (Windows 11, Home included).** On by default on clean installs; when the cloud cannot vouch for a file and it
  is unsigned, SAC blocks it, and "there is currently no way to bypass Smart App Control protection for individual apps" **[H]**.
  SAC checks *all* executables, not just downloads **[H]** — so on a SAC machine the installed `PlayMap.exe`, its DLLs and the
  supervisor are blocked too, not only the installer. Recent Windows 11 updates let SAC be switched off and on without a reinstall
  **[H]**, though reports in early 2026 say turning it back on still needed a registry value **[M]**. SAC logs blocks as event 3077 in
  `Microsoft-Windows-CodeIntegrity/Operational` **[H]**.
- **Windows 11 Home in S mode** installs Store apps only; switching out is free and one-way **[H]**.

What PlayMap can do while unsigned: publish SHA-256 hashes beside each artifact; `docs/INSTALL.md` states the three prompts and the
SAC switch; a preflight or `machine.install` row can report SAC's state (`HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy\
VerifiedAndReputablePolicyState`: 0 off, 1 on, 2 evaluation **[H]**) as information. Signing later does not involve WiX: Microsoft's
Artifact Signing starts at $9.99 a month **[H]** (§9 decision 2 in the plan).

## 5. Windows 11 Home specifics that touch the installer

- MSI and EXE installers, services, firewall rules, WER keys and LSA rights all work on Home **[M]** (no edition gate in the
  Windows Installer or SCM documentation).
- **Shell Launcher is not available on Home or Pro** — Enterprise, Education and IoT Enterprise only **[H]**. On Home the engine
  reaches the show user's session through the supervisor (`WTSQueryUserToken`/`CreateProcessAsUser`) or the plan's logon scheduled
  task; auto-logon is configured outside the MSI.
- No Group Policy editor on Home; SAC and S mode are the edition's own gates (§4).

## 6. Recommendation, in full

**Primary: WiX v7, compiled from source, one per-machine MSI** — as `design/installer.md` specifies, with three changes:

1. `PLAN.md` §9 decision 3 becomes an answer: *no fee; the WiX toolset is compiled from its MS-RL source at a pinned tag in CI;
   PlayMap never downloads WiX's binary releases, NuGet packages or .NET tool, and files no WiX issues.*
2. `.github/workflows/build.yml` gains the `wix-toolset` job (§2.4), cached by tag; `nuget.config` maps `WixToolset.*` to the local
   feed only; `InstallerTests` assert the source of the restored SDK. No `AcceptEula` property appears anywhere (the agreement does
   not apply to self-built binaries).
3. `THIRD-PARTY-NOTICES.md` names WiX as a build tool and its Util/Firewall custom-action DLLs inside the MSI as MS-RL files with a
   source link.

**Spike (first item of wp3-installer, time-boxed to one day on `windows-latest`):** build the pinned tag; produce the SDK and the
Util and Firewall extension packages; build a hello MSI with a `ServiceInstall`, a `MajorUpgrade` and a firewall rule; install,
upgrade and uninstall it quietly on the runner; record build time and cache size; record whether the self-built `wix` still asks for
the EULA gesture and how it is answered (a build property or a one-line patch kept in PlayMap's pin notes).

**Fallback, if the spike fails or the build cost is out of proportion:** Inno Setup 7.1 (64-bit installer), with every machine-level
action in the supervisor's own verbs, the downgrade and armed checks in `InitializeSetup`, Cancel rollback for files, and the MSI
version rules restated for an EXE (no 255 limit; ordering by the four-part file version). This loses MSI's transactional rollback
of service and registry changes, repair, and `msiexec`-native IT deployment (Intune still deploys an EXE as a Win32 app **[M]**).

**Not recommended:** WiX v5 except as a short stopgap (no security fixes); WiX v7 official binaries (a fee as soon as revenue
crosses $10 000, and a CI attestation that can silently become false); MSIX, ClickOnce, Velopack, Squirrel (no fit for a LocalSystem
supervisor and machine-level writes); VS Installer Projects (IDE-only build); a home-made MSI generator (weeks, owned forever).

**What would change it:** the spike failing on the runner (→ Inno Setup); the owner choosing to sponsor WiX (→ official v7, simpler
CI); a decision to publish through the Microsoft Store (→ MSIX, re-signed by the Store, no SmartScreen prompt **[H]**).
