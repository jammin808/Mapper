# Where PlayMap stands

*PlayMap's competitive position: the field, the matrix, and what to learn from each. Every third-party fact carries a source URL. **Estimate** marks our own judgement, not a measurement.*

**How to read the sources.** The research pass read most vendor pages through search-result summaries, because many vendor domains (madmapper.com, resolume.com, dataton.com, disguise.one, pixera.one, help.disguise.one and others) did not resolve from our build environment. A final fact check on 12 October could not re-open those domains and had no search budget left. So:

- **(verified)** means re-read from a primary source on 12 Oct 2026.
- **(unverified)** means it comes from the research pass and could not be re-checked. Confirm it before quoting it outside the team. Version numbers, release dates and prices are the facts most likely to be wrong.
- **unknown** means we found no source.

Vendor capability claims are the vendors' own. We have tested none of these products ourselves.

## 1. The short answer

**No. PlayMap is not better than MadMapper today, and it is not in the class of disguise, Pixera or Watchout.** It has never put a frame on a real projector.

Status of main:
- All ten modules are merged and tested, and `PlayMap engine [headless]` composes the real media, render, network and scan backends. The desk starts and watches this machine's engine or attaches to a node on the network; it has a show strip (Ready, ARM, PANIC, Blackout), greys every control with the node's own words before a press, shows every package's STATE on a card and builds Add effect, Modulate, Bind, Optimise and Use input entries from the node's answers. It has Health ▸ Fleet, Preflight and Calibration, the blind chip and panel, and MAP's quad tool and on-wall mode. The sync board has no desk view of its own: its verbs run from the cards and over the wire.
- The round-two work is built on simulators: show safety, vblank truth and the frame lock, the Direct3D 11 flip-model path as an explicit, experimental choice, the HAP family on the GPU, hardware decode kept on the GPU where the renderer can take it, optimise to HAP on import, OSC, MIDI, Art-Net and sACN input with bindings, timecode chase, Companion (the node's side and the module), ISF effect chains, audio analysis and modulation, generative content, pixel quads and the calibration ledger, camera auto-align, fleet health and a hot backup with a manual takeover, LED pixel mapping, video in and out over OMT, NDI and Spout, facades and projector stacks, and scans from many places (docs/ROADMAP.md §0).
- No real camera, projector, sync board, SAM model or second machine has been used; the GL tests run on Mesa's software renderer. Every scan, solve and device test runs against simulators or protocol fixtures.

**By design, PlayMap aims past MadMapper in 3D calibration, multi-node sync and automation. That is a hypothesis until a lab publishes RMS figures from real hardware** (docs/ROADMAP.md, Round 1). No lab exists this round, so every claim that only hardware can prove is reported not run, never passed. Scope is not robustness. Our simulators do not model rolling shutter, auto-exposure, projector image processing, interreflection or subsurface scattering, and those are what break structured light in real rooms.

Five design ideas we have not found combined in one product:

1. **Structured-light calibration with commodity cameras and no per-output licence.** High-end autocal mostly comes with vendor camera kits (disguise OmniCal, Christie Mystique, Modulo's PoE-camera module) or per-channel licences (VIOSO). That is not universal: VIOSO accepts NDI cameras, MadMapper's Space Scanner takes a DSLR, webcam or NDI camera, and Panasonic, Epson and Christie sell camera-based geometry and blend for their own projectors (§3b). Our difference is the combination: free, any camera, curved surfaces, projectors from any maker.
2. **Masks and warps stored in surface UV space, separate from playlists.** A fix made at the venue applies to every playlist. When only a projector moves, masks and warps survive by construction. When the mesh itself changes, survival needs the retargeting work in ROADMAP R4.7.
3. **Each frame is a pure function of leader show time.** This makes timecode chase clean, and it makes a backup node a live mirror **for deterministic sources** (files, generators, `SET`s scheduled with `AT`). Live inputs, web pages, audio analysis and unscheduled edits break frame identity between nodes (§5c).
4. **One verb vocabulary, a full machine-readable STATE, and MCP with risk-gated approvals.** The desk has no private API.
5. **Ray-pick and highlight verbs over a calibrated projector-to-surface map, offered to thin clients.** disguise and Pixera also hold a 3D world model and expose APIs, so the world model alone is not unique. What we have not seen is that model offered as "send a ray, get back the surface, and see it light up on the object". That is the primitive phone and glasses control needs (docs/XR.md).

**What "frame-accurate sync" means here.** Every node picks the same frame index for a given show time. Without genlock, the moment that frame reaches the projector can differ by up to one refresh between nodes. That ±1 refresh figure is a design target and has not been measured. Presenting on the same vblank needs framelock (ROADMAP R4.2).

**Where PlayMap is behind, and stays behind until it is built:**
- **Output smoothness:** OpenGL 3.3 core or ES 3.00 and one render thread; each output measures its vblanks and presents. The Direct3D 11 flip-model path is an explicit, experimental choice that has run only on WARP; the frame-lock machine is built, but its NVAPI tier is compile-only and joins no swap group.
- **Codecs:** the HAP family decodes on the GPU and clips optimise to HAP on import; hardware decode of other codecs keeps its frames on the GPU where the renderer can take them (VAAPI sampled in place, D3D11VA with one copy on the GPU), else copies them back, and none of it has run on a real GPU.
- **Video IO:** OMT, NDI and Spout in and out are built (OMT over loopback, NDI against a fake runtime, Spout on WARP); no capture-card SDKs yet: capture devices open through FFmpeg's avdevice.
- **Control:** OSC, MIDI, Art-Net and sACN input with bindings, timecode chase and the Companion module are built; no MIDI out or OSCQuery.
- **Show floor:** Show Mode, locks, panic, blind edit, preflight, fleet health and a hot backup with a manual takeover are built; no automatic takeover, and no backup has run on a second machine.
- **Creative breadth:** ISF effect chains, audio reactivity and LED pixel mapping are built; no FFGL, laser output or export.
- **Adoption:** no importers from other tools, no installer yet, no reference hardware list, no support offer, and one maintainer.

**Where PlayMap is going.** Round 3 (`docs/round3/PLAN.md`) is to make PlayMap an installed, Windows-native show node on every edition of Windows 11, Home included, from a per-machine installer, built with Inno Setup this round (an MSI is revisited next round), that is unsigned for now and named so. Direct3D 12 becomes the primary renderer behind an RHI, each output on its own flip-model swap chain; OpenGL stays the reference backend until pixel and timing parity is measured. Outputs lock in hardware where the hardware allows it (on RTX PRO with RTX PRO Sync: NVIDIA's present barrier on Direct3D 12, the WGL swap group on OpenGL), each output locked only by its own evidence; everywhere else they run the software lock, which publishes its measured phase. Capture cards pass through to an output with one frame in flight. The desk opens on guided workflows (two projectors blended or stacked on a flat screen, a film mapped onto a wall so it reads undistorted from the audience, an object mapped with one or two projectors) beside advanced panes and a console. Every command is in the menu bar and the right-click menus, every mapping step can be done by hand, and the assistant proposes each step's lines through the same gate as everyone's. Of it, only the rendering hardware interface is built, with GL behind it; the rest is not built yet, and none of it changes the answer above until it has run on hardware.

## 5. Is PlayMap better than MadMapper or the high end?

### 5a. Today

No, on every axis that counts on a job. A tool that has never played a frame through a real projector cannot be compared on smoothness, setup time or reliability.

The output path is a specific risk. On Windows, the documented route to reliable vblank timing and independent flip is a DXGI flip-model swap chain with frame statistics. OpenGL presentation goes through each driver's own path (estimate, our engineering judgement). PlayMap presents through OpenGL 3.3 core or ES 3.00 by default, with one render thread for every output; each output keeps a vblank clock and a present ledger, so a missed vblank is counted, not guessed. The Direct3D 11 flip-model path is built as an explicit, experimental choice (`PRESENT PATH DXGI`) and has run only on WARP. A MadMapper forum thread reports staff steering Windows users towards Direct3D output for VBL sync, and users moving a stuttering four-projector HAP blend to Watchout ([forum](https://forum.garagecube.com/viewtopic.php?f=20&t=36303); unverified, and one thread is an anecdote, not a measurement). We do not need that thread to make the decision. PlayMap's direction is Direct3D 12 behind an RHI, presenting through DXGI's flip model, with OpenGL kept as the reference until pixel and timing parity is measured; the Direct3D 11 path then retires with OpenGL (§8).

### 5b. By design, per user

| User | Better than MadMapper by design? | Better than disguise / Pixera / Watchout by design? | What decides it |
|---|---|---|---|
| **3D mapping artist** | **Likely, if the scan works on real materials.** MadMapper's 3D calibration is manual point matching. PlayMap has structured light, self-calibration, ICP to LiDAR, 3D auto-blend and UV-anchored work in code, tested only on simulators | **Narrower in scope until mid-term.** They have field hardening, multi-camera solves and mesh deform. PlayMap solves many views of many projectors together by verb, but takes its views through one camera at a time (ROADMAP M3), and mesh deform is R4.7 | Time to a good image on a tested webcam; robustness on bad materials; a mesh-deform and export round trip |
| **Corporate AV tech** | **Yes, once it runs:** multi-node sync, content distribution, projector control, STATE | **Not until** redundancy and framelock run on real machines (Show Mode, preflight, Companion and a hot backup with a manual takeover are built; none has run on a second machine). Then cost wins. Projectors' own autocal also competes here (§3b) | Mirror backup, a pre-show health page, re-align after a bump in ≤60 s; the flat guide (two projectors blended or stacked on a flat screen) by hand to a blended canvas within 10 minutes (round 3's lab line L24, not run) |
| **Permanent install / museum** | Yes: scheduler, unattended re-check and drift watch are planned | Close to OmniCal recal and Atlas with calibration as a service (R4.8, built in large part as `CALIBRATION` and `ALIGN`) | Nightly check with a score gate, boot to show, fleet view |
| **VJ / club** | **No.** MadMapper, Resolume and HeavyM win on effects, audio, MIDI learn, LED/DMX and live ergonomics (PlayMap has ISF chains, audio modulation, `BIND LEARN` and LED output, but not their depth or the instrument layer) | n/a | Interop first (Spout, OMT, NDI, OSC/MIDI), then the instrument layer |
| **Touring / broadcast programmer** | n/a | **No** until framelock, 10-bit output, ST 2110 and automatic failover exist (timecode chase and a hot backup with a manual takeover are built) | LTC chase as a fitted anchor; the hardware lock (NVIDIA's present barrier on Direct3D 12, the swap group on OpenGL); mirror failover |
| **AI / automation integrator** | Possibly: we found no MCP or AI layer in MadMapper | Possibly: disguise has an AI assistant; we found none in Watchout or Pixera; Resolume reportedly ships local MCP. **PlayMap's risk gate has never gated a live show** | Safe, staged, risk-gated actions proven in rehearsal |

**Bottom line.** By design, PlayMap should beat MadMapper for 3D artists, corporate AV and installs, and lose to it for VJs. It reaches the high end only on calibration accessibility, recovery without rework and automation, and only after the roadmap's show-floor work (its Rounds 2–4). Until a lab runs it on hardware, and none exists this round, every "better" in this table is a hypothesis. Our public message should say exactly that.

### 5c. Design claims that need care

| Claim | Where it holds | Where it does not |
|---|---|---|
| Backup node is a live mirror | Files, generators, `SET`s scheduled with `AT`, all on both nodes | Live capture, NDI/Spout/OMT inputs (they arrive at different times), web pages, audio analysis, stateful or feedback generators, unscheduled operator edits. These need a "non-deterministic source" badge and a fix ("capture to HAP", or feed both nodes from one router) |
| Failover is seamless | The backup's frames are identical for deterministic sources | Switch time is set by the projector or router re-locking: often 0.5–3 s unless the projector has a seamless backup-input feature (estimate). A Videohub switch is not frame-synchronised |
| Masks survive a rescan | When only a projector moved: by construction (masks live in UV) | When the mesh changed: needs retargeting (R4.7) |
| Glasses pick surfaces precisely | Whole surfaces and snapped nodes | Freehand points. Pointer error, not map accuracy, is the limit (docs/XR.md) |
| A box mapped in ≤2 minutes | A target with a pattern budget (docs/UX.md §5.1) | Not measured. Depends on a camera with manual exposure |

## 6. The market moved in 2026: what that means for us

1. **"Phone scan, surfaces appear" is now a product category.** IllumiBeast, AIMapper, Artemis and Ghost Arcade all launched or updated in 2026 (sources in §3a; details unverified). PlayMap's thesis is right but no longer alone. We must win on three things: fully local, curved surfaces, and multiple projectors from any maker.
2. **MCP is not a moat.** Community MCP servers exist for TouchDesigner, and Resolume reportedly ships local MCP. An MCP server is easy to copy. Our edge is safe action on a live show: risk gates, staging, Show Mode. That edge is only real once it has run a rehearsal.
3. **Calibration is becoming an operational service at the high end.** disguise reportedly added a RigCheck API, out-of-focus camera detection and an OmniCal Score in r32.4 ([disguise news](https://www.disguise.one/kr/node/7691); unverified). VYV keeps a calibration history and applies a new result only within a reference gate ([VYV](https://www.vyv.ca/en/docs/calibration/automatic-calibration-and-real-time-alignment-guide/); unverified). Scalable demos deliberately break and re-run calibration on the show floor ([SVC](https://www.svconline.com/the-wire/scalable-display-technologies-to-showcase-automated-projection-mapping-on-large-scale-mount-rushmore-display-at-infocomm-2026)).
4. **The high end is reaching down.** disguise Designer Pro is $1,500 a year, and software-only X-series tiers were reported (§3a; unverified). Our price advantage is real, but it may be against a cheaper disguise than before.
5. **NDI is useful but proprietary.** Its SDK has its own licence terms. Avolites reportedly removed NDI from Titan, Prism and Ai in Dec 2025 citing licensing changes ([Avolites](https://www.avolites.com/avolites-release-titan-v19-important-information/); unverified). We keep NDI optional either way (§8).
6. **Spatial control of live stages exists, but not for projection mapping.** ETC ships phone and tablet AR in Eos through Augment3d ([ETC](https://www.etcconnect.com/About/News/Eos-gets-Augment3d-with-the-release-of-Eos-v3-0.aspx)). Unreal Engine has VR scouting and a Remote Control web app for virtual production stages (source needed). We found no projection-mapping or media-server vendor shipping headset or glasses look-and-control (as of Oct 2026; not exhaustive). The nearest mapping prior art is prototypes: Spatial Mapper on Snap Spectacles ([write-up](https://rbkavin.studio/insights/building-spatial-mapper-snap-spectacles.html)) and Project Ion on visionOS ([TestFlight](https://testflight.apple.com/join/hzXHAZ4B)). See docs/XR.md.

## 9. Codec and IO plan

Rounds and IDs refer to docs/ROADMAP.md; "round 3 (wp3-…)" names the round under way and its package (docs/round3/PLAN.md), not the roadmap's near-term Round 3. The professional baseline is the HAP family, NotchLC, ProRes and H.264/HEVC, plus NDI. Vendor performance tables (for example [disguise VX 4+ performance](https://help.disguise.one/hardware/performance/vx4plus-performance); figures not re-verified) consistently show GPU-decoded codecs carrying many times more 4K layers than ProRes, so GPU codecs must be the default show path.

## 10. Legal, licensing and security risks

| Risk | What we do |
|---|---|
| **FFmpeg LGPL inside the installer** | Today no FFmpeg is shipped: the portable exe loads the shared libraries the user puts in place. Round 3's installer carries the pinned LGPL build, configured `--enable-version3` and so LGPL version 3 or later, as separate shared libraries the user can replace (docs/round3/PLAN.md §9 decision 4); no `--enable-nonfree` and no GPL-only components; licence notices and a source offer in the package |
| **The Direct3D 12 runtime's terms** | Round 3's installer carries the Agility SDK's `D3D12Core.dll`. Microsoft's licence lets it be distributed on its Distribution Requirements, among them to "require distributors and external end users to agree to terms that protect it and Microsoft at least as much as this agreement" and to "indemnify, defend, and hold harmless Microsoft from any claims, including attorneys’ fees, related to the distribution or use of your applications, except to the extent that any claim is based solely on the unmodified distributable code", with its Distribution Restrictions beside them (no trademark use that suggests Microsoft's endorsement; no relicensing that would require its source be disclosed). The installer shows a licence page that carries Microsoft's own licence for `D3D12Core.dll` verbatim, PlayMap's own terms being the owner's to name, and the owner accepts Microsoft's distribution terms, including indemnifying Microsoft (docs/round3/PLAN.md §9 decision 23 quotes them whole) |
| **H.264 / HEVC patents** | Prefer OS and GPU decoders. Get legal advice before shipping any software encoder for these codecs |
| **Model licences** | SAM 3 is released under Meta's SAM License ([arXiv 2511.16719](https://arxiv.org/pdf/2511.16719)); review it before redistributing weights. Check the licence of every ONNX export we pin, not only the original model. | **Calibration patents** | Christie holds patents on the structured-light pipeline ([US10574956](https://patents.google.com/patent/US10574956)), coarse-mesh model correction ([US10403028](https://patents.google.com/patent/US10403028)) and drift correction from reduced pattern sets ([US20200092524](https://patents.justia.com/patent/20200092524)). | **YouTube terms** | See §9 |
| **Prompt injection** | Media file names, metadata, web-page sources and STATE fields that remote clients can write all reach the assistant's context. They are data, never instructions. High-risk verbs always wait for a human. While armed, the assistant can only queue proposals |
| **Web content on a show node** | CEF runs sandboxed in its own process, with no file or device access, and is off by default |
| **Exposed HTTP / MCP on venue networks** | TLS and pairing exist, and every verb that changes something needs pairing. MCP is served by default; the posture to ship is MCP off until enabled (ROADMAP R3.14). Round 3's installer adds the firewall rules once, on the private and domain profiles, and preflight names a show network on the Public profile without a rule |
| **Unsigned binaries** | Today's portable exe is unsigned. Round 3's installer stays unsigned for now, each build named `-unsigned` with a `SHA256SUMS` file, which shows a download is intact, not who built it. SmartScreen and UAC name an unknown publisher, antivirus may flag unsigned native code (FFmpeg, ONNX Runtime), and corporate IT may block it. Smart App Control, once it enforces, blocks unsigned code before PlayMap runs, so round 3's release page and install guide say so before the download. Signing is the next round's (docs/round3/PLAN.md §9 decision 2). PlayMap has no updater, and round 3's installer refuses to run while the node answers armed. On Windows 11 Home, Windows Update cannot be deferred: a person pauses it past the show, and round 3's preflight says so |
